# 退化场景目录（variants）

> 每个变体回答一个具体问题，阈值来自实测（docs/EVIDENCE.md G3）。全部纯 JS 实现，无 GPU、无随机数。

## 参与判定的变体（失败 → verdict 降为 warn）

| id | 变换 | 回答的问题 | 默认 148px 产物 |
|---|---|---|---|
| `downscale-2x` | 最近邻缩到 1/2 | 屏幕缩小显示、缩略图场景还能读吗 | 通过 |
| `blur-1px` | 1px 盒式模糊（两次 pass 近似高斯） | 轻微失焦/低分辨率相机还能读吗 | 通过 |
| `rotate-5deg` | 最近邻旋转 5°，白底填充 | 拍摄角度偏移还能读吗 | 通过 |
| `rotate-15deg` | 同上 15° | 更大倾角 | 通过 |
| `low-light` | 亮度 ×0.55 + 偏移 110 | 背光不足 + 黑位抬升 | 通过 |
| `speckle` | 1% 像素被确定性置黑/白 | 印刷噪点、传感器噪点 | 通过 |

## 边界变体（只展示，不参与判定）

| id | 变换 | 为什么不算缺陷 |
|---|---|---|
| `downscale-3x` | 缩到 1/3 | 实测 148px→49px 失败，但 200px→66px、296px→98px 都通过。它衡量**绝对尺寸**，不是缩放比。作为必须项会让大图和小图混为一谈。 |
| `glare` | 圆形高光，中心在左上定位图案，半径 0.4R，强度 1.0 | 实测居中/居上高光即使覆盖半图半径仍可读；只有**盖住定位图案**才失效。作为必须项等于要求"任何高光都不能有"，过严。 |

`optional` 变体的结果仍完整出现在报告表格里（标注"（边界，不参与判定）"），
也会出现在 `variants` 数组的 `optional: true` 字段上，供调用方自行取用。

## 为什么不用 sharp / canvas 做变换

早期版本用过 `sharp`（实测可用，VIPS 8.18.7）。放弃的理由：

1. **可复现性**：`sharp` 的 resize/blur 结果依赖 VIPS 版本，不同平台可能差几个像素；
   报告一旦含这类差异就不可比。
2. **安装成本**：`sharp` 是原生模块，在受限环境（CI 容器、某些 ARM 板）装不上，
   会让"验收"这件事本身变成环境问题。
3. **它现在是可选依赖的邻居**：本包只保留 `pngjs` 这种纯 JS 依赖做 PNG 编解码，
   变换全部自己写（`lib/scanproof/variants.js`，约 150 行）。

代价是变换比 `sharp` 慢（完整 8 个变体约 210ms），这个代价换来的是"任何装了 Node 的机器上结论一致"。

## 确定性验证

`test/scanproof/variants.test.js` 有一条断言：对每个变体连续应用两次，逐字节比较输出。
这条测试存在的意义是防止将来有人往变换里塞 `Math.random()` 或时间种子——
一旦发生，报告就不再可复现，而"可复现"是这份报告唯一的价值来源。

## 加新变体的检查清单

1. 变换必须纯 JS、无外部依赖、无随机数；
2. 先在默认产物上实测通过，再确定阈值（记录进 docs/EVIDENCE.md）；
3. 判断它是"必须通过"还是"边界场景"——若换个基础尺寸结论就反转，它属于边界；
4. 在 `VARIANTS` 里写清楚它回答的问题，`label` 要让人一眼知道做了什么变换；
5. 补一条确定性断言。
